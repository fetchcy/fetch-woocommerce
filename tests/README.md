# Tests

- `php tests/unit.php` — webhook signature, order mapping rules, price markup maths, request batching, deactivation rows, masked customer details, the per-order import lock (on in-memory SQLite), the "Mirror this shop 1:1" scan, plan, 50% guard and switch-off batches (against a fake API), default-language-only sync with stubbed WPML filters and Polylang functions (originals vs translations, shared SKUs, variations, save and delete hooks, the mirror's kept set, order lookup, no plugin), the product content sent to Fetch (brand detection and the "Brand attribute" setting, specs from global and local attributes, plain-text descriptions with paragraphs, Yoast / Rank Math SEO meta, the API size limits), and several Fetch stores (a 1.3.0 config read as one connected store with its keys unchanged, per-store settings and their fallbacks, per-store option names, meta keys and job arguments, markups, category filters with subcategories, switch-off of a product leaving a store's categories, per-store queues and deletions, the per-store mirror keep set, and one store's API error not touching the other), no WordPress needed.
- `node tests/e2e/run.mjs` — boots WordPress Playground with WooCommerce and this plugin, points it at a local mock of the Fetch Partner API (`mock-fetch.mjs`), and runs the full flow: product sync, stock change, price markup resync, batches over 200 rows, delete/trash, order import, accept, status changes, masked customer details, webhook + poll races, signed/unsigned webhooks, and "Mirror this shop 1:1" (mode off, preview, switch-off of listings with no ref / a foreign ref / an excluded product, a product coming back, a failed scan page, a failed push, the over-50% guard and "Apply anyway", batches over 200 rows), and a multilingual shop on Polylang (installed in the Playground, activated near the end): only English products and variations are sent, a translation sharing the SKU does not overwrite the original, the preview in wp-admin with Polylang's language filter on Greek, mirror switch-off of listings from translations, order stock on the original, deleting translations, and the "Synced language" readout; then a product with a global "Brands" attribute, local and global specs, HTML descriptions and SEO meta, and the "Brand attribute" setting.; then several Fetch stores from one site: the key sees three stores, the shop connects two (one with its own 20% markup and only the Dogs categories), and the test checks the store list and checkboxes, the full sync of the newly connected store, which products and prices reach each store and that nothing reaches the third, per-store queues and flush jobs, the per-store status row, an order from the second store imported and tagged with it (order box line and orders-list column), accepted against that store, its stock reduction sent to both stores, webhooks routed by storeId (one for an unconnected store ignored and logged once), one store's API error not blocking the other, mirror on one store not touching the other, disconnecting a store, and a fresh connection through the form. The mock keeps each store's listings and orders, pages `GET /listings` with `nextCursor`, and applies the live `listings/batch` rules. Outbound HTTP from WordPress is blocked (`WP_HTTP_BLOCK_EXTERNAL`) so only the mock is reached, and WP-cron is off (`DISABLE_WP_CRON`): every Action Scheduler job is run by the test itself, so none runs in the background mid-step. Needs internet the first time (downloads Playground + WooCommerce). Takes ~4–6 minutes.
- `node tests/e2e/upgrade.mjs` — the upgrade from 1.3.0: runs the plugin as released in 1.3.0 (taken from git; `UPGRADE_FROM=<ref>` picks another version), connects it, syncs products with a 10% markup, imports an order and leaves a full sync queued, then replaces the plugin files with this checkout's. It checks the shop is still connected to the same store with the same settings, the 1.3.0 product data and queued job are used as they are, stock changes still sync, the old order is accepted against its store, and a full sync creates no duplicate products on Fetch.
- Both e2e runners accept `E2E_PLUGIN_CACHE=<dir>` holding `woocommerce.zip` and `polylang.zip` (from downloads.wordpress.org), which they mount instead of letting Playground download them, for networks where those downloads fail.
